# M10c — Jump-Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connections through an intermediate host (ProxyJump, ONE hop): optional jump block in the form with its own login choice (login set/manual), its own TOFU flow for both hops, persisted in the session, resolved on export.

**Architecture:** Citadel's built-in `SSHClient.jump(to:)` (direct-tcpip + full SSH session with its own validator) makes the connect two-stage; the TOFU retry logic becomes a bounded loop (max. two accept retries, one per hop). `StoredSession.JumpSpec` (nested, decode-compatible) with its own keychain slot `secretID`; resolution via `LoginResolver.resolveJump`; all mutations (save/delete/set-delete-restore/export) in `SessionListViewModel`. The app wires the toggle + jump block with the M10b three-way building blocks.

**Tech Stack:** Swift 6 / `.swiftLanguageMode(.v5)`, Swift Testing, SwiftUI, Citadel (pinned — `jump(to:)` verified in `.build/checkouts/Citadel/Sources/Citadel/Client.swift:197`).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-m10c-jump-host-design.md` — binding. Mockup: `docs/design/assets/m10-mockups.html` section 2. Branch: **develop**.
- TOFU INVARIANTS UNTOUCHED on EVERY hop: mismatch = hard stop (decider is NEVER asked), unknown only with explicit consent, no accept-anything path. Every accept upserts; the same key is never prompted twice.
- Secrets NEVER in JSON: manual jump secrets in the keychain under `JumpSpec.secretID` (its own slot — the session slot belongs to the target); set mode uses the set slot (M10b). Orphaned slots are cleaned up (session delete, jump removal, manual→set switch).
- `StoredSession.jump: JumpSpec?` optional WITHOUT a custom decoder (groupID/loginSetID pattern) — legacy JSON reads nil.
- A missing referenced jump set on connect = HONEST error (M10b pattern), no silent fallback. Jump auth error = new case `RemoteFSError.jumpAuthenticationFailed` (additive; `isConnectionFailure` stays false for it).
- ONE hop; merge detection stays target-only; no "save as new set" in the jump block; no ssh-config ProxyJump import.
- Export stays format v1 with ADDITIVE optional jump fields; export never aborts; jump password only with `includePasswords`.
- All new UI text EN/DE (`L10n.string`, both catalogs); code + comments English ONLY; no new dependencies.

- [x] **Step 4: Two-stage connect.** Rework of `connect`/`attemptConnect` in `CitadelFileSystem.swift`:

```swift
    // Privater Marker, damit die äußere Schleife Stufe-1-Fehler (Jump)
    // von Stufe-2-Fehlern unterscheiden kann, OHNE die Box-Auswertung zu
    // stören (Host-Key-Verdicts laufen weiter über die Boxen):
    private struct JumpStageError: Error { let underlying: Error }

    public static func connect(config:knownHosts:onUnknownHostKey:) async throws -> CitadelFileSystem {
        var acceptRetries = 0
        let maxAcceptRetries = config.jump == nil ? 1 : 2  // one per hop
        while true {
            let jumpBox = TOFUHostKeyValidator.Box()
            let targetBox = TOFUHostKeyValidator.Box()
            do {
                return try await attemptConnect(config:, knownHosts:, jumpBox:, targetBox:)
            } catch {
                // Pro Versuch kann höchstens EIN Hop ein Verdict tragen
                // (Stufe 2 startet erst nach erfolgreicher Stufe 1) — Jump
                // zuerst prüfen.
                let verdict = firstVerdict(jumpBox, targetBox)   // kleine Hilfsfunktion
                switch verdict {
                case .mismatch(...): throw HostKeyError.mismatch(...)          // wie bisher
                case .lookupFailed(let reason): throw RemoteFSError.connectionFailed(...)
                case .unknown(let candidate):
                    guard acceptRetries < maxAcceptRetries else { throw mapStageAware(error) } // defensiv
                    let accepted = await onUnknownHostKey(candidate)
                    guard accepted else { throw HostKeyError.rejectedByUser }
                    try knownHosts.upsert(KnownHostKey(host: candidate.host, ...))
                    acceptRetries += 1
                    continue                                                    // voller Re-Connect beider Hops
                case .none: throw mapStageAware(error)
                }
            }
        }
    }
    // mapStageAware: JumpStageError(underlying) ->
    //   allAuthenticationOptionsFailed => RemoteFSError.jumpAuthenticationFailed
    //   sonst => RemoteFSError.connectionFailed(reason: "jump host: \(mapped reason)")
    //   (SSHKeyError des Jump-Keys durchreichen — trägt eigenen Kontext);
    // alles andere -> bestehendes mapConnectError (Ziel-Semantik unverändert).

    private static func attemptConnect(config:, knownHosts:, jumpBox:, targetBox:) async throws -> CitadelFileSystem {
        // Ziel-Auth wie bisher aufbauen (authMethod aus config.auth).
        if let jump = config.jump {
            // Stufe 1 — eigener do/catch, Fehler als JumpStageError markiert:
            let jumpClient: SSHClient
            do {
                let jumpAuth = /* config-analog aus jump.auth (Loader für Keys) */
                let jumpValidator = TOFUHostKeyValidator(host: jump.host, port: jump.port,
                                                         knownHosts: knownHosts, box: jumpBox)
                jumpClient = try await SSHClient.connect(
                    host: jump.host, port: jump.port,
                    authenticationMethod: jumpAuth,
                    hostKeyValidator: .custom(jumpValidator), reconnect: .never)
            } catch { throw JumpStageError(underlying: error) }
            // Stufe 2 — jeder Fehler ab hier schließt den Jump-Client:
            do {
                let targetValidator = TOFUHostKeyValidator(host: config.host, port: config.port,
                                                           knownHosts: knownHosts, box: targetBox)
                let settings = SSHClientSettings(
                    host: config.host, port: config.port,
                    authenticationMethod: { authMethod },
                    hostKeyValidator: .custom(targetValidator))
                let client = try await jumpClient.jump(to: settings)
                do {
                    let sftp = try await client.openSFTP()
                    return CitadelFileSystem(client: client, sftp: sftp, jumpClient: jumpClient)
                } catch { try? await client.close(); throw error }
            } catch let error as JumpStageError { throw error   // unreachable, Klarheit
            } catch { try? await jumpClient.close(); throw error }
        }
        // jump == nil: heutiger Pfad byte-identisch (validator auf targetBox).
    }
```

**Behavioral requirements (spec §2/§4, binding):**
1. Decode compatibility: sessions.json WITHOUT a `jump` field reads nil (no custom decoder); roundtrip preserves the JumpSpec including secretID.
2. Slot hygiene in save/updateSession: if the OLD session had a manual jump (`jump != nil, loginSetID == nil`) and the NEW one has no jump OR a jump in set mode ⇒ delete the old `secretID` slot (throw-free `try?`). `delete(_ session:)` additionally deletes the jump slot.
3. `deleteLoginSet` (M10b extension): sessions with `jump.loginSetID == set.id` are ALSO restored — the set's username/authKind/keyPath copied into the JumpSpec, the set secret into the JumpSpec's `secretID` slot, `jump.loginSetID = nil`; the count shares `restored`/`secretFailures` with the target restoration (a session with BOTH a target AND a jump reference counts once, both references get restored). `sessionsUsing(setID:)`/`usageCount(of:)` count jump references too (the delete confirmation and the usage counter in the sheet line up automatically as a result).
4. `exportPayload`: sessions with a jump export the jump fields RESOLVED (`resolveJump`; set ⇒ set values; `jumpPassword` only with `includePasswords`, a missing secret counts in `missingPasswordCount`); a missing jump set exports the spec's own values (export never aborts). Sessions without a jump: all six fields nil (encodes compactly — the synthesized encoder's `encodeIfPresent` behavior is sufficient).
5. Import: `SessionImportPlanner` threads the jump fields into the planned session (JumpSpec with a FRESH `secretID`, loginSetID always nil — sets are not imported); `applyImport` stores `jumpPassword` under the fresh secretID (keychain error counts in `passwordFailures`). Old files without jump fields ⇒ nil (decode-compatible in both directions).
6. `reload()`/existing APIs otherwise unchanged.
