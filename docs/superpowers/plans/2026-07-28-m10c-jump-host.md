# M10c — Jump-Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verbindungen über einen Zwischenhost (ProxyJump, EIN Hop): optionaler Jump-Block im Formular mit eigener Login-Wahl (Login-Set/Manuell), eigener TOFU-Fluss für beide Hops, persistiert in der Session, aufgelöst im Export.

**Architecture:** Citadels eingebautes `SSHClient.jump(to:)` (direct-tcpip + volle SSH-Session mit eigenem Validator) macht den Connect zweistufig; die TOFU-Retry-Logik wird zur begrenzten Schleife (max. zwei Accept-Retries, einer pro Hop). `StoredSession.JumpSpec` (verschachtelt, decode-kompatibel) mit eigenem Keychain-Slot `secretID`; Auflösung über `LoginResolver.resolveJump`; alle Mutationen (Save/Delete/Set-Lösch-Rückstellung/Export) in `SessionListViewModel`. Die App verdrahtet Toggle + Jump-Block mit den M10b-Dreiweg-Bausteinen.

**Tech Stack:** Swift 6 / `.swiftLanguageMode(.v5)`, Swift Testing, SwiftUI, Citadel (gepinnt — `jump(to:)` in `.build/checkouts/Citadel/Sources/Citadel/Client.swift:197` verifiziert).

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-m10c-jump-host-design.md` — bindend. Mockup: `docs/design/assets/m10-mockups.html` Abschnitt 2. Branch: **develop**.
- TOFU-INVARIANTEN UNANGETASTET auf JEDEM Hop: Mismatch = harter Stopp (Decider wird NIE gefragt), unknown nur mit explizitem Consent, kein Accept-Anything-Pfad. Jeder Accept upserted; derselbe Key prompted nie zweimal.
- Secrets NIE in JSON: manuelle Jump-Secrets im Keychain unter `JumpSpec.secretID` (eigener Slot — der Session-Slot gehört dem Ziel); Set-Modus nutzt den Set-Slot (M10b). Verwaiste Slots werden aufgeräumt (Session-Delete, Jump-Entfernen, Manuell→Set-Wechsel).

- Alle neuen UI-Texte EN/DE (`L10n.string`, beide Kataloge); Code + Kommentare NUR Englisch; keine neuen Dependencies.

- [x] **Step 4: Zweistufiger Connect.** Umbau von `connect`/`attemptConnect` in `CitadelFileSystem.swift`:

```swift
    // Privater Marker, damit die äußere Schleife Stufe-1-Fehler (Jump)
    // von Stufe-2-Fehlern unterscheiden kann, OHNE die Box-Auswertung zu
    // stören (Host-Key-Verdicts laufen weiter über die Boxen):
    private struct JumpStageError: Error { let underlying: Error }

    public static func connect(config:knownHosts:onUnknownHostKey:) async throws -> CitadelFileSystem {
        var acceptRetries = 0
        let maxAcceptRetries = config.jump == nil ? 1 : 2  // one per hop
        while true {
            let jumpBox = TOFUHostKeyValidator.Box()
            let targetBox = TOFUHostKeyValidator.Box()
            do {
                return try await attemptConnect(config:, knownHosts:, jumpBox:, targetBox:)
            } catch {
                // Pro Versuch kann höchstens EIN Hop ein Verdict tragen
                // (Stufe 2 startet erst nach erfolgreicher Stufe 1) — Jump
                // zuerst prüfen.
                let verdict = firstVerdict(jumpBox, targetBox)   // kleine Hilfsfunktion
                switch verdict {
                case .mismatch(...): throw HostKeyError.mismatch(...)          // wie bisher
                case .lookupFailed(let reason): throw RemoteFSError.connectionFailed(...)
                case .unknown(let candidate):
                    guard acceptRetries < maxAcceptRetries else { throw mapStageAware(error) } // defensiv
                    let accepted = await onUnknownHostKey(candidate)
                    guard accepted else { throw HostKeyError.rejectedByUser }
                    try knownHosts.upsert(KnownHostKey(host: candidate.host, ...))
                    acceptRetries += 1
                    continue                                                    // voller Re-Connect beider Hops
                case .none: throw mapStageAware(error)
                }
            }
        }
    }
    // mapStageAware: JumpStageError(underlying) ->
    //   allAuthenticationOptionsFailed => RemoteFSError.jumpAuthenticationFailed
    //   sonst => RemoteFSError.connectionFailed(reason: "jump host: \(mapped reason)")
    //   (SSHKeyError des Jump-Keys durchreichen — trägt eigenen Kontext);
    // alles andere -> bestehendes mapConnectError (Ziel-Semantik unverändert).

    private static func attemptConnect(config:, knownHosts:, jumpBox:, targetBox:) async throws -> CitadelFileSystem {
        // Ziel-Auth wie bisher aufbauen (authMethod aus config.auth).
        if let jump = config.jump {
            // Stufe 1 — eigener do/catch, Fehler als JumpStageError markiert:
            let jumpClient: SSHClient
            do {
                let jumpAuth = /* config-analog aus jump.auth (Loader für Keys) */
                let jumpValidator = TOFUHostKeyValidator(host: jump.host, port: jump.port,
                                                         knownHosts: knownHosts, box: jumpBox)
                jumpClient = try await SSHClient.connect(
                    host: jump.host, port: jump.port,
                    authenticationMethod: jumpAuth,
                    hostKeyValidator: .custom(jumpValidator), reconnect: .never)
            } catch { throw JumpStageError(underlying: error) }
            // Stufe 2 — jeder Fehler ab hier schließt den Jump-Client:
            do {
                let targetValidator = TOFUHostKeyValidator(host: config.host, port: config.port,
                                                           knownHosts: knownHosts, box: targetBox)
                let settings = SSHClientSettings(
                    host: config.host, port: config.port,
                    authenticationMethod: { authMethod },
                    hostKeyValidator: .custom(targetValidator))
                let client = try await jumpClient.jump(to: settings)
                do {
                    let sftp = try await client.openSFTP()
                    return CitadelFileSystem(client: client, sftp: sftp, jumpClient: jumpClient)
                } catch { try? await client.close(); throw error }
            } catch let error as JumpStageError { throw error   // unreachable, Klarheit
            } catch { try? await jumpClient.close(); throw error }
        }
        // jump == nil: heutiger Pfad byte-identisch (validator auf targetBox).
    }
```

**Verhaltens-Anforderungen (Spec §2/§4, bindend):**
1. Decode-Kompat: sessions.json OHNE `jump`-Feld liest nil (kein Custom-Decoder); Roundtrip erhält die JumpSpec inkl. secretID.
2. Slot-Hygiene in save/updateSession: hatte die ALTE Session einen manuellen Jump (`jump != nil, loginSetID == nil`) und die NEUE hat keinen Jump ODER Jump im Set-Modus ⇒ alten `secretID`-Slot löschen (throw-frei `try?`). `delete(_ session:)` löscht zusätzlich den Jump-Slot.
3. `deleteLoginSet` (M10b-Erweiterung): Sessions mit `jump.loginSetID == set.id` werden AUCH zurückgestellt — username/authKind/keyPath des Sets in die JumpSpec kopiert, Set-Secret in den `secretID`-Slot der JumpSpec, `jump.loginSetID = nil`; Zählung teilt sich `restored`/`secretFailures` mit der Ziel-Rückstellung (eine Session mit Ziel- UND Jump-Referenz zählt einmal, beide Referenzen werden zurückgestellt). `sessionsUsing(setID:)`/`usageCount(of:)` zählen Jump-Referenzen mit (Lösch-Rückfrage + Nutzungszähler im Sheet stimmen dadurch automatisch).
4. `exportPayload`: Sessions mit Jump exportieren die Jump-Felder AUFGELÖST (`resolveJump`; Set ⇒ Set-Werte; `jumpPassword` nur bei `includePasswords`, fehlendes Secret zählt in `missingPasswordCount`); fehlendes Jump-Set exportiert die Spec-Eigenwerte (Export bricht nie ab). Sessions ohne Jump: alle sechs Felder nil (encodet kompakt — `encodeIfPresent`-Verhalten des synthesized Encoders reicht).
5. Import: `SessionImportPlanner` reicht die Jump-Felder in die geplante Session durch (JumpSpec mit FRISCHER `secretID`, loginSetID immer nil — Sets werden nicht importiert); `applyImport` speichert `jumpPassword` unter der frischen secretID (Keychain-Fehler zählt in `passwordFailures`). Alt-Dateien ohne Jump-Felder ⇒ nil (decode-kompat beide Richtungen).
6. `reload()`/bestehende APIs sonst unverändert.
