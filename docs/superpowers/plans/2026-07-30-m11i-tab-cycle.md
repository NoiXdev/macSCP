# M11i — Durch die Kandidaten blättern: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Wiederholtes Tab in der Pfadeingabe blättert durch die Kandidaten, Shift+Tab zurück, Esc bricht das Blättern ab, ohne die Eingabe zu verlieren.

**Architecture:** Reine App-Änderung an `PathBar.swift` plus eine kleine, testbare Zyklus-Funktion in Core. Kein Eingriff in `PathCompletion` oder `navigate(to:)`.

**Tech Stack:** Swift 6 (`.swiftLanguageMode(.v5)`), SwiftUI + AppKit, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-07-30-m11i-tab-cycle-design.md`

## Global Constraints

- Code und Kommentare **nur Englisch**; Anzeigetexte über die Kataloge.
- Kein bestehendes `@State`-Feld ändert seine Bedeutung — nur additiv.
- Der Blätter-Modus ist an `lastCandidates` gebunden; eine neue Tab-Runde
  setzt ihn zurück (M11g-Sorgfalt gegen späte Listings).
- Die M7-Regel (Shift+Tab verwirft außerhalb des Blätterns) bleibt gültig.
- **Kein App-Test-Target**: die Zyklus-Rechnung wird als reine Funktion
  ausgelagert und getestet; der Rest geht in die Smoke-Checkliste.
- `swift build` immer aus einem SAUBEREN Build-Verzeichnis prüfen (ein
  inkrementeller Lauf verschweigt Warnungen).
- Tests: Swift Testing, TDD. Baseline: **775 Tests / 55 Suiten**.
- Kein Release, kein Merge auf `main`, kein Tag.

### Task 1: Zyklus-Funktion + Tab-Blättern + Esc (Core-Kleinigkeit + App)

**Files:**
- Create: `Sources/macSCPCore/RemoteFS/CandidateCycle.swift`
- Test: `Tests/macSCPCoreTests/CandidateCycleTests.swift`
- Modify: `Sources/MacSCPApp/PathBar.swift`

**Interfaces:**
- Produces (Core): `public enum CandidateCycle` mit
  `public static func next(from current: Int?, count: Int) -> Int?` und
  `public static func previous(from current: Int?, count: Int) -> Int?` —
  `nil`/`count == 0` ⇒ `nil`; `next(nil, n) == 0`; `next(n-1, n) == 0`
  (Umbruch); `previous(nil, n) == n-1`; `previous(0, n) == n-1`.
- Consumes (App): das bestehende `handleTab()`, `lastCandidates`,
  `lastCandidatesDirectory`, `overlayContent`, `CandidatesList`,
  `PathTextField`s `insertBacktab`-Zweig, `cancel()`.

- [x] **Step 1: Failing tests für `CandidateCycle`** (`CandidateCycleTests`):
  vorwärts aus `nil` ⇒ 0; vorwärts am Ende ⇒ 0 (Umbruch); rückwärts aus
  `nil` ⇒ letzter; rückwärts von 0 ⇒ letzter; `count == 0` ⇒ `nil` in
  beiden Richtungen; `count == 1` ⇒ immer 0.

- [x] **Step 2: Rot beweisen.** `swift test --filter CandidateCycle` → FAIL.

- [x] **Step 3: `CandidateCycle` implementieren** (rein, wenige Zeilen).

- [x] **Step 4: Grün.** `swift test --filter CandidateCycle` → PASS.

- [x] **Step 5: Zwei neue `@State` in `PathBar`.**
  `cycleIndex: Int?` (nil = nicht im Blätter-Modus) und
  `cycleBaseDraft: String`. In `beginEditing()` und in jeder neuen
  Tab-Runde (dort, wo `justCompletedWithTab = true` gesetzt wird und ein
  frisches Listing startet) `cycleIndex = nil` setzen — der Blätter-Modus
  darf nie an eine alte Liste gebunden bleiben. Kommentar mit der
  Begründung (späte-Listing-Sorgfalt).

- [x] **Step 6: `handleTab()` erweitern.**
  Wenn die Kandidatenliste sichtbar/verfügbar ist (`justCompletedWithTab`
  und `lastCandidates` nicht leer und `lastCandidatesDraft == draft`
  ODER bereits im Blätter-Modus):
  - `cycleIndex = CandidateCycle.next(from: cycleIndex, count: lastCandidates.count)`;
  - beim ersten Schritt (vorheriger `cycleIndex == nil`) `cycleBaseDraft = draft` merken;
  - `draft = RemotePath.join(lastCandidatesDirectory, lastCandidates[cycleIndex!]) + "/"`;
  - `overlayContent = .candidates(lastCandidates)` mit dem neuen
    `selectedIndex` (siehe Step 8).
  Der bestehende erste-Tab-Weg (Listing + `completedInput`) bleibt
  unverändert; nur der „schon eine Liste"-Zweig bekommt das Blättern statt
  des bloßen erneuten Anzeigens.

- [x] **Step 7: Shift+Tab und Esc.**
  - In `PathTextField`s `control(_:textView:doCommandBy:)`: `insertBacktab`
    ruft, **solange die Liste offen ist**, einen neuen Closure
    `onBacktab()` und gibt `true` zurück (kein Fokuswechsel); ist die Liste
    NICHT offen, weiter `return false` wie bisher (M7 unangetastet). Ob die
    Liste offen ist, weiß die View — den Zustand über den Closure oder ein
    übergebenes Flag prüfen, nicht im `PathTextField` selbst raten.
    `onBacktab` macht dasselbe wie ein Tab, nur mit
    `CandidateCycle.previous`.
  - Esc: der `onCancel`-Weg (`cancel()`) bekommt eine Vorstufe — ist
    `cycleIndex != nil`, dann `draft = cycleBaseDraft`, `cycleIndex = nil`,
    `overlayContent = nil`, **Feld bleibt offen** (kein `isEditing = false`).
    Sonst wie bisher schließen. Das gilt sowohl für den AppKit-Weg als auch
    für die SwiftUI-Verdrahtung, damit es nur eine Regel gibt.

- [x] **Step 8: Hervorhebung + Scroll in `CandidatesList`.**
  `CandidatesList` bekommt `selectedIndex: Int?`. Der Eintrag an diesem
  Index erhält die `remoteSoft`-Auswahl-Fläche (wie die M5g-Tabellen-
  Auswahl) und wird über einen `ScrollViewReader` in den sichtbaren Bereich
  gescrollt. `overlayContent` muss den Index mittragen — entweder als
  zusätzliches Assoziiertes im `.candidates`-Fall oder über ein separates
  `@State`, das zusammen mit dem Overlay gesetzt wird. Ohne Auswahl sieht
  die Liste aus wie heute (reiner 2.-Tab-Zustand vor dem ersten Blättern).

- [x] **Step 9: Verifikation.**
  `swift build` aus sauberem Build-Verzeichnis (keine neuen Warnungen; vier
  vorbestehende sind erwartet), volle `swift test`. `PathBar` hat kein
  Test-Target — die Zyklus-Funktion ist der automatisierte Teil, der Rest
  ist Smoke.

- [x] **Step 10: Commit.** `feat: cycle through path completion candidates with Tab`
