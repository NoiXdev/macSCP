# M11g — Interaktive Pfadzeile: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die Pfadzeile im Pane-Kopf wird bedienbar — Klick kopiert, Doppelklick öffnet eine manuelle Eingabe, Tab vervollständigt im Shell-Stil.

**Architecture:** Eine reine Core-Funktion rechnet die Vervollständigung über einem übergebenen Verzeichnis-Listing aus (keine I/O); das ViewModel bekommt ein `navigate(to:)` mit ehrlichen Fehlermeldungen; die App ersetzt den `Text` im Pane-Kopf durch eine Zeile, die Kopieren, Eingabe, Tab und Kandidatenliste beherrscht.

**Tech Stack:** Swift 6 (`.swiftLanguageMode(.v5)`), SwiftUI, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-07-30-m11g-path-bar-design.md`

## Global Constraints

- Code und Kommentare **nur Englisch**; Anzeigetexte über die Kataloge
  (`Localizable.strings`, EN Default + DE), niemals hartkodiert. Deutsche
  Texte nur mit typografischen Anführungszeichen („…“) — ein ASCII-`"`
  macht die ganze deutsche Datei ungültig (M11d-Blocker).
- `PathCompletion` macht **keine** I/O: das Listing wird übergeben.
- `caseSensitive` ist ein **Parameter ohne Default** — die Gegenseite ist es
  in der Regel, ein lokales macOS-Dateisystem nicht.
- Nur **Verzeichnisse** sind Vervollständigungs-Kandidaten.
- Fehlerhafte Eingabe lässt das Feld OFFEN mit Meldung; der getippte Text
  geht nie verloren.
- Kein Breadcrumb, kein Verlauf, kein Globbing, keine `~`-Auflösung, kein
  Audit-Eintrag.
- Tests: Swift Testing, TDD rot→grün. Baseline vor T1: **737 Tests / 54 Suiten**.
- Kein Release, kein Merge auf `main`, kein Tag.

**Interfaces:**
- Consumes: `RemoteFileItem` (`isDirectory`, `name`, `path`), `RemotePath.join/parent`, das `RemoteFileSystem`-Protokoll (`list`, `stat`), das `String?`-Fehlermuster der M7b-Aktionen.
- Produces (T2 verlässt sich wörtlich darauf):
  - `public enum PathCompletion`
    - `public struct Result: Equatable, Sendable { public let completedInput: String; public let candidates: [String] }`
    - `public static func complete(input: String, entries: [RemoteFileItem], caseSensitive: Bool) -> Result`
    - `public static func directoryToList(for input: String) -> String` — welches Verzeichnis die App listen muss, damit `complete` etwas ausrechnen kann
  - `RemoteBrowserViewModel.navigate(to path: String) async -> String?`

- [ ] **Step 1: Failing tests für `PathCompletion`.**

Fixture-Helfer für Einträge (Ordner und Dateien), dann diese Fälle:
- `directoryToList(for:)`: `"/var/www/ho"` ⇒ `"/var/www"`; `"/var/www/"` ⇒ `"/var/www"`; `"/var"` ⇒ `"/"`; `"/"` ⇒ `"/"`.
- eindeutiger Treffer: Einträge `html/` (Ordner), Input `"/var/www/ht"` ⇒ `completedInput == "/var/www/html/"`, `candidates == ["html"]`.
- mehrere Kandidaten, gemeinsames Präfix wird ergänzt: Ordner `hosts`,
  `home-alt`, `holiday` (gemeinsames Präfix `"ho"`), Input `"/var/www/h"`
  ⇒ `completedInput == "/var/www/ho"`, `candidates == ["holiday", "home-alt", "hosts"]`.
- mehrere Kandidaten, deren gemeinsames Präfix nicht über das Getippte
  hinausgeht: Ordner `html` und `hosts` (gemeinsames Präfix `"h"`), Input
  `"/var/www/h"` ⇒ `completedInput` bleibt `"/var/www/h"`,
  `candidates == ["hosts", "html"]`.
- kein Treffer: Input `"/var/www/zz"` ⇒ `completedInput` unverändert, `candidates == []`.
- Trailing-Slash listet alles: Input `"/var/www/"` ⇒ alle Ordner als Kandidaten, `completedInput` unverändert wenn kein gemeinsames Präfix, sonst ergänzt.
- **Dateien sind nie Kandidaten**: Einträge `index.html` (Datei) und `images/` (Ordner), Input `"/var/www/i"` ⇒ `completedInput == "/var/www/images/"`, `candidates == ["images"]`.
- Groß-/Kleinschreibung: Ordner `Docs`, Input `"/home/d"` mit `caseSensitive: true` ⇒ kein Treffer; mit `caseSensitive: false` ⇒ `"/home/Docs/"`. **Wichtig:** bei `caseSensitive: false` wird die Schreibweise des ECHTEN Eintrags übernommen, nicht die getippte.
- leeres Listing ⇒ `candidates == []`, Input unverändert.
- Wurzel: Input `"/"` mit Ordnern `etc`, `usr` ⇒ Kandidaten beide, `completedInput == "/"`.
- Leerzeichen in Komponenten: Ordner `My Files`, Input `"/home/My"` ⇒ `"/home/My Files/"` (kein Quoting, kein Escaping).
- Symlinks: ein Eintrag mit `kind == .symlink` ist KEIN Kandidat (wir wissen ohne `stat` nicht, ob er auf ein Verzeichnis zeigt — dieselbe Zurückhaltung wie in `PermissionsTreeApplier`).

- [ ] **Step 2: Rot beweisen.** `swift test --filter PathCompletion` → FAIL.

- [ ] **Step 3: `PathCompletion` implementieren.**

Rein, ohne I/O. `directoryToList` nimmt den Input, schneidet nach dem
letzten `/` ab und normalisiert per `RemotePath` (Wurzel bleibt `"/"`).
`complete` filtert `entries` auf `isDirectory` (Symlinks ausgeschlossen),
vergleicht die letzte Komponente per Präfix (je `caseSensitive` mit
`hasPrefix` bzw. `lowercased()`-Vergleich), berechnet aus den Treffern das
längste gemeinsame Präfix **in der Schreibweise der echten Einträge** und
baut `completedInput` aus dem Elternverzeichnis plus diesem Präfix — bei
genau einem Treffer mit abschließendem `/`, damit direkt weitergetippt
werden kann. `candidates` sind die Treffer-Namen alphabetisch
(`localizedCaseInsensitiveCompare`).

Doc-Kommentare (Englisch) müssen begründen: warum nur Verzeichnisse, warum
Symlinks ausgeschlossen sind, warum `caseSensitive` ein Parameter ohne
Default ist, und warum die Schreibweise vom echten Eintrag kommt.

- [ ] **Step 4: Failing tests für `navigate(to:)`** in `RemoteBrowserViewModelTests` (Mock-FS wie die bestehenden M7b-Aktionstests):
- Erfolg: Sprung auf ein existierendes Verzeichnis setzt `currentPath`, lädt, leert die Auswahl, liefert `nil`.
- Ziel ist eine **Datei** ⇒ eigene Meldung (nicht dieselbe wie „existiert nicht"), `currentPath` unverändert.
- Ziel existiert **nicht** ⇒ eigene Meldung, `currentPath` unverändert.
- Rechte-Fehler des FS ⇒ dessen Meldung wird durchgereicht, `currentPath` unverändert.
- Slash-Normalisierung: `"/var//www///"` landet auf `"/var/www"` — und ein Test mit DOPPELTEM Trailing-Slash, weil einmaliges Strippen dort nachweislich nicht genügt (M7a-Lektion).
- leerer String und `"   "` ⇒ Meldung, kein Sprung.

- [ ] **Step 5: Rot beweisen, dann implementieren.**
`navigate(to:)` normalisiert (Schleife, nicht einmaliges Strippen),
`stat`et das Ziel, unterscheidet Datei / nicht vorhanden / FS-Fehler mit je
eigener lokalisierter Meldung, setzt bei Erfolg `currentPath` und ruft
`load()`. Neue Keys in BEIDE Core-Kataloge (EN zuerst, DE mit
typografischen Anführungszeichen).

- [ ] **Step 6: Gated Rig-Test** in `CitadelFileSystemITests`: Sprung in ein
tiefes Verzeichnis und zurück auf `/`, plus eine Vervollständigung gegen
ein ECHTES Listing des Rigs (beweist, dass `directoryToList` + `list` +
`complete` zusammenpassen — die reinen Tests können das nicht).

- [ ] **Step 7: Grün + volle Suite.** `swift test` → 737 + neue; `plutil -lint` auf alle vier Kataloge.

- [ ] **Step 8: Commit.** `feat: complete and navigate to typed paths`

### Task 2: Pfadzeile (App)

**Files:**
- Create: `Sources/MacSCPApp/PathBar.swift`
- Modify: `Sources/MacSCPApp/BrowserPane.swift` (der `Text` in Zeile ~49 wird ersetzt), `Sources/MacSCPApp/Resources/{en,de}.lproj/Localizable.strings`

**Interfaces:**
- Consumes: `PathCompletion`, `RemoteBrowserViewModel.navigate(to:)`, `viewModel.currentPath`, das FS des Panes für das Listing.
- Produces: nichts für spätere Tasks.

- [ ] **Step 1: Anzeigezustand.** `PathBar` zeigt standardmäßig denselben
  Text wie heute — 11,5 pt monospaced, `DesignTokens.inkTertiary`,
  `lineLimit(1)`, `.truncationMode(.middle)`, linksbündig in
  `frame(maxWidth: .infinity)`. Die Optik darf sich im Ruhezustand NICHT
  ändern (M5g hat diese Maße gegen das Mockup abgeglichen).

- [ ] **Step 2: Klick kopiert.** Einfacher Klick schreibt
  `viewModel.currentPath` in `NSPasteboard.general` (clearContents zuerst)
  und zeigt für ~1,5 s eine Bestätigung anstelle des Pfades oder daneben.
  Zeiger auf `.pointingHand`, damit die Fähigkeit auffindbar ist. Neuer
  Katalog-Key.

- [ ] **Step 3: Doppelklick öffnet die Eingabe.** Ein `TextField`, vorbelegt
  mit `currentPath`, Fokus und Cursor am Ende. **Enter** ruft
  `navigate(to:)`; **Esc** und **Fokusverlust** verwerfen. Vorbild für das
  Fokus-Handling und die Verwerfen-Regel ist das Inline-Umbenennen in
  `SessionSidebar` — dort abschauen, nicht neu erfinden. Achtung auf die
  M5k-Falle: außerhalb einer `Form` surfacen `TextField`-Titel als
  In-Field-Placeholder, deshalb explizit `Text(verbatim: "")` als Prompt.

- [ ] **Step 4: Tab vervollständigt.** Tab im Feld: das Verzeichnis aus
  `PathCompletion.directoryToList(for:)` über das FS des Panes listen,
  `complete(input:entries:caseSensitive:)` aufrufen, `completedInput`
  übernehmen. `caseSensitive` ist `true` für die Gegenseite und `false`
  lokal — die Seite kennt `BrowserPane` über `side`. Ein zweites,
  unmittelbar folgendes Tab klappt `candidates` unter dem Feld auf
  (anklickbar, Klick übernimmt); jeder andere Tastendruck schließt die
  Liste. Das Listing läuft in einem `Task`; die Eingabe bleibt bedienbar.

- [ ] **Step 5: Fehler.** Die Meldung aus `navigate(to:)` erscheint unter
  dem Feld, das Feld bleibt offen und behält den Text. Erst ein
  erfolgreicher Sprung schließt es.

- [ ] **Step 6: EN/DE.** Alle neuen Keys in BEIDE App-Kataloge, Englisch
  zuerst, Deutsch mit typografischen Anführungszeichen. `plutil -lint` auf
  alle vier Kataloge OK, `LocalizableStringsTests` grün.

- [ ] **Step 7: Verifikation.** `swift build` (0 Fehler, keine neuen
  Warnungen), volle `swift test`.

- [ ] **Step 8: Commit.** `feat: make the pane path bar interactive`
