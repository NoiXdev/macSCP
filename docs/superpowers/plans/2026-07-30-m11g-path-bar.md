# M11g — Interactive Path Bar: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The path bar in the pane header becomes interactive — click copies, double-click opens manual entry, Tab completes shell-style.

**Architecture:** A pure Core function computes completion over a supplied directory listing (no I/O); the view model gets a `navigate(to:)` with honest error messages; the app replaces the `Text` in the pane header with a line that handles copy, entry, Tab, and a candidate list.

**Tech Stack:** Swift 6 (`.swiftLanguageMode(.v5)`), SwiftUI, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-07-30-m11g-path-bar-design.md`

## Global Constraints

- Code and comments **English only**; display text via the
  catalogs (`Localizable.strings`, EN default + DE), never hardcoded. German
  text only with typographic quotation marks („…") — an ASCII `"`
  invalidates the entire German file (M11d blocker).
- `PathCompletion` does **no** I/O: the listing is supplied.
- `caseSensitive` is a **parameter without a default** — the remote side
  usually is one, a local macOS filesystem is not.
- Only **directories** are completion candidates.
- Invalid input leaves the field OPEN with a message; the typed text
  is never lost.
- No breadcrumb, no history, no globbing, no `~` resolution, no
  audit entry.
- Tests: Swift Testing, TDD red→green. Baseline before T1: **737 tests / 54 suites**.
- No release, no merge to `main`, no tag.

### Task 1: PathCompletion + navigate(to:) (Core)

**Files:**
- Create: `Sources/macSCPCore/RemoteFS/PathCompletion.swift`
- Modify: `Sources/macSCPCore/Presentation/RemoteBrowserViewModel.swift`
- Modify: `Sources/macSCPCore/Resources/{en,de}.lproj/Localizable.strings`
- Test: `Tests/macSCPCoreTests/PathCompletionTests.swift`, `Tests/macSCPCoreTests/RemoteBrowserViewModelTests.swift` (extend), `Tests/macSCPCoreTests/CitadelFileSystemITests.swift` (gated, extend)

**Interfaces:**
- Consumes: `RemoteFileItem` (`isDirectory`, `name`, `path`), `RemotePath.join/parent`, the `RemoteFileSystem` protocol (`list`, `stat`), the `String?` error pattern of the M7b actions.
- Produces (T2 relies on this literally):
  - `public enum PathCompletion`
    - `public struct Result: Equatable, Sendable { public let completedInput: String; public let candidates: [String] }`
    - `public static func complete(input: String, entries: [RemoteFileItem], caseSensitive: Bool) -> Result`
    - `public static func directoryToList(for input: String) -> String` — which directory the app must list so `complete` has something to compute over
  - `RemoteBrowserViewModel.navigate(to path: String) async -> String?`

- [x] **Step 1: Failing tests for `PathCompletion`.**

Fixture helpers for entries (folders and files), then these cases:
- `directoryToList(for:)`: `"/var/www/ho"` ⇒ `"/var/www"`; `"/var/www/"` ⇒ `"/var/www"`; `"/var"` ⇒ `"/"`; `"/"` ⇒ `"/"`.
- unambiguous match: entries `html/` (folder), input `"/var/www/ht"` ⇒ `completedInput == "/var/www/html/"`, `candidates == ["html"]`.
- multiple candidates, common prefix gets appended: folders `hosts`,
  `home-alt`, `holiday` (common prefix `"ho"`), input `"/var/www/h"`
  ⇒ `completedInput == "/var/www/ho"`, `candidates == ["holiday", "home-alt", "hosts"]`.
- multiple candidates whose common prefix does not extend beyond what was
  typed: folders `html` and `hosts` (common prefix `"h"`), input
  `"/var/www/h"` ⇒ `completedInput` stays `"/var/www/h"`,
  `candidates == ["hosts", "html"]`.
- no match: input `"/var/www/zz"` ⇒ `completedInput` unchanged, `candidates == []`.
- trailing slash lists everything: input `"/var/www/"` ⇒ all folders as candidates, `completedInput` unchanged if there is no common prefix, otherwise appended.
- **Files are never candidates**: entries `index.html` (file) and `images/` (folder), input `"/var/www/i"` ⇒ `completedInput == "/var/www/images/"`, `candidates == ["images"]`.
- Case sensitivity: folder `Docs`, input `"/home/d"` with `caseSensitive: true` ⇒ no match; with `caseSensitive: false` ⇒ `"/home/Docs/"`. **Important:** with `caseSensitive: false`, the casing of the REAL entry is used, not the typed casing.
- empty listing ⇒ `candidates == []`, input unchanged.
- root: input `"/"` with folders `etc`, `usr` ⇒ both are candidates, `completedInput == "/"`.
- spaces in components: folder `My Files`, input `"/home/My"` ⇒ `"/home/My Files/"` (no quoting, no escaping).
- symlinks: an entry with `kind == .symlink` is NOT a candidate (we cannot know without `stat` whether it points to a directory — the same restraint as in `PermissionsTreeApplier`).

- [x] **Step 2: Prove red.** `swift test --filter PathCompletion` → FAIL.

- [x] **Step 3: Implement `PathCompletion`.**

Pure, no I/O. `directoryToList` takes the input, cuts after the
last `/` and normalizes via `RemotePath` (root stays `"/"`).
`complete` filters `entries` on `isDirectory` (symlinks excluded),
compares the last component by prefix (per `caseSensitive`, using
`hasPrefix` or a `lowercased()` comparison), computes the longest common
prefix over the hits **in the casing of the real entries**, and
builds `completedInput` from the parent directory plus that prefix — for
exactly one match, with a trailing `/` so typing can continue
directly. `candidates` are the matching names, alphabetically
(`localizedCaseInsensitiveCompare`).

Doc comments (English) must explain: why only directories, why
symlinks are excluded, why `caseSensitive` is a parameter without a
default, and why the casing comes from the real entry.

- [x] **Step 4: Failing tests for `navigate(to:)`** in `RemoteBrowserViewModelTests` (mock FS, like the existing M7b action tests):
- Success: jumping to an existing directory sets `currentPath`, loads, clears the selection, returns `nil`.
- Target is a **file** ⇒ its own message (not the same as "does not exist"), `currentPath` unchanged.
- Target does **not** exist ⇒ its own message, `currentPath` unchanged.
- FS permission error ⇒ its message is passed through, `currentPath` unchanged.
- Slash normalization: `"/var//www///"` ends up as `"/var/www"` — plus a test with a DOUBLE trailing slash, because a single strip demonstrably does not suffice there (M7a lesson).
- empty string and `"   "` ⇒ message, no jump.

- [x] **Step 5: Prove red, then implement.**
`navigate(to:)` normalizes (a loop, not a single strip),
`stat`s the target, distinguishes file / not present / FS error each with its
own localized message, sets `currentPath` on success and calls
`load()`. New keys in BOTH Core catalogs (EN first, DE with
typographic quotation marks).

- [x] **Step 6: Gated rig test** in `CitadelFileSystemITests`: jump into a
deep directory and back to `/`, plus one completion against a REAL
listing from the rig (proves that `directoryToList` + `list` +
`complete` fit together — the pure tests cannot prove that).

- [x] **Step 7: Green + full suite.** `swift test` → 737 + new; `plutil -lint` on all four catalogs.

- [x] **Step 8: Commit.** `feat: complete and navigate to typed paths`

### Task 2: Path bar (App)

**Files:**
- Create: `Sources/MacSCPApp/PathBar.swift`
- Modify: `Sources/MacSCPApp/BrowserPane.swift` (the `Text` around line ~49 is replaced), `Sources/MacSCPApp/Resources/{en,de}.lproj/Localizable.strings`

**Interfaces:**
- Consumes: `PathCompletion`, `RemoteBrowserViewModel.navigate(to:)`, `viewModel.currentPath`, the pane's FS for the listing.
- Produces: nothing for later tasks.

- [x] **Step 1: Display state.** `PathBar` shows, by default, the same
  text as today — 11.5 pt monospaced, `DesignTokens.inkTertiary`,
  `lineLimit(1)`, `.truncationMode(.middle)`, left-aligned in
  `frame(maxWidth: .infinity)`. The look at rest MUST NOT
  change (M5g matched these measurements against the mockup).

- [x] **Step 2: Click copies.** A single click writes
  `viewModel.currentPath` to `NSPasteboard.general` (clearContents first)
  and shows a confirmation in place of, or next to, the path for ~1.5 s.
  Cursor `.pointingHand` so the capability is discoverable. New
  catalog key.

- [x] **Step 3: Double-click opens entry.** A `TextField`, pre-filled
  with `currentPath`, focus and cursor at the end. **Enter** calls
  `navigate(to:)`; **Esc** and **loss of focus** discard. The model for
  the focus handling and the discard rule is the inline rename in
  `SessionSidebar` — copy that, don't reinvent it. Watch out for the
  M5k trap: outside a `Form`, `TextField` titles surface as
  in-field placeholders, so use an explicit `Text(verbatim: "")` as the prompt.

- [x] **Step 4: Tab completes.** Tab in the field: list the directory from
  `PathCompletion.directoryToList(for:)` via the pane's FS,
  call `complete(input:entries:caseSensitive:)`, adopt
  `completedInput`. `caseSensitive` is `true` for the remote side and `false`
  locally — the side knows about `BrowserPane` via `side`. A second, immediately
  following Tab expands `candidates` below the field
  (clickable, click adopts it); any other key press closes the
  list. The listing runs in a `Task`; the input stays usable.

- [x] **Step 5: Errors.** The message from `navigate(to:)` appears below
  the field, the field stays open and keeps the text. Only a
  successful jump closes it.

- [x] **Step 6: EN/DE.** All new keys in BOTH app catalogs, English
  first, German with typographic quotation marks. `plutil -lint` on
  all four catalogs OK, `LocalizableStringsTests` green.

- [x] **Step 7: Verification.** `swift build` (0 errors, no new
  warnings), full `swift test`.

- [x] **Step 8: Commit.** `feat: make the pane path bar interactive`
