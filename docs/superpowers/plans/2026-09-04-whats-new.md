# What's New Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the first launch after a version change the app shows what
changed since the version last seen; Settings gains a "What's new"
entry that shows the same list for every version.

**Architecture:** The release script already writes `CHANGELOG.md` in
the conventional-changelog shape (a `## [1.3.0](…) (2026-08-31)`
heading per version, `### Features` / `### Bug Fixes` sections, one
bullet per commit with a scope and a link). Core gains a parser,
`ChangelogParser` (`Sources/macSCPCore/Updates/Changelog.swift`), that
turns that text into `[ChangelogRelease]` (version, date, sections of
entries with scope and text, links dropped). The bundle ships the file
(`Resources/CHANGELOG.md` copied by `scripts/package-app` and the dev
build script); the app reads it through the same resource lookup
`L10n` uses (never `Bundle.module`). `SettingsStore.lastSeenVersion`
holds the version last shown; at launch, when it differs from
`CFBundleShortVersionString`, a sheet lists the releases newer than it
and then records the current version. Settings gets a pane "What's
new" listing all releases, newest first.

**Tech Stack:** Swift 6 strict, SwiftUI, Swift Testing, `SettingsStore`,
the release/package scripts, four catalogs.

**Spec:** `docs/BACKLOG.md`, row "What's new: a changelog dialog after
an update, and in Settings" (maintainer feedback 2026-09-04). Measured
at HEAD: `CHANGELOG.md` exists at the repo root (1.3.0 the newest
entry); the version is read at `SettingsView.swift:181` and
`UpdateCheckModel.swift:136` from `Bundle.main`; `SettingsView`'s panes
are the `enum` at `:10-19` (general … s3).

## Global Constraints

- English only in the tree; user-facing strings only via `L10n.string` in all four catalogs (German du); the changelog TEXT itself is English and shown as is (it is the release record, not UI copy); Conventional Commits; footer exactly `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`; commit per task; zero warnings; do not push.
- The parser is total: an unknown line is kept as plain text under the current section, never dropped silently, never a crash; a file with no headings yields an empty list.
- No `Bundle.module`; the resource lookup mirrors `L10n`'s candidate list and falls back to "no changelog shipped" text.
- The sheet appears once per version change and never on a fresh install (no last-seen version → record the current one, show nothing); a downgrade shows nothing.
- Red first; no `#require` on a non-optional; no wall-clock ceiling; tests never block the pool; a negative check needs a positive beside it; a number in a comment is counted; the existing Settings guards stay green.
- Do NOT launch the GUI.
