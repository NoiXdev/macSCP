# Unbounded File Closes: Measure First — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer the one question the entry asks — does `SFTPFile.close()`
return when the peer goes silent mid-transfer? — with a measurement
against a frozen container, on both the read and the write path, and
record the numbers. **No deadline is added by this plan.**

**Architecture:** One gated test per path in
`Tests/macSCPAppKitTests/LivenessProbeDropIntegrationTests.swift`, which
already owns the disposable-container helpers (`DisposableSSHServer` with
`freeze()`/`thaw()`, `connectToSSHServer(port:)`, `Docker`, all
`private` to that file — so the tests live there). Each test freezes the
container mid-transfer, cancels the transfer task, and measures whether
the cancellation branch — the one that calls `try? await handle.close()`
/ `try? await file.close()` — returns within a bound. Every postcondition
is read BEFORE the thaw.

**Tech Stack:** Swift 6, Swift Testing, Docker (`docker run/pause/unpause/rm`
through the file's `Docker` helper), `CitadelFileSystem.readStream` /
`write`.

**Source:** `docs/superpowers/specs/2026-08-28-backlog-unbounded-file-closes.md`
— "measure first, do not bound it"; the technique in
`.superpowers/sdd/frozen-peer-measurement.md` (may be gone — the
in-tree pattern is `teardownAgainstAStillFrozenPeerTerminates` in the same
test file).

## Global Constraints

- Code, comments, test names, commit message: **English only**. Conventional
  Commits; footer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- **Measure, do not fix.** No deadline, no `BoundedClose`, no change under
  `Sources/` in this plan. If the close does NOT return, that is the result;
  the fix is a separate plan with this test as its red.
- **Read before you heal** (CLAUDE.md "Tests that watch a defect heal"):
  `returned`, elapsed time and every other postcondition are snapshotted
  BEFORE `thaw()`. A test that thaws and then reads has measured nothing.
- **Sensitivity is a number**: run each measurement **3 times**; report all
  three durations. One run is evidence that something can happen, not that
  it does.
- Gated only (`MACSCP_ITEST=1`); the container is disposable (own port, own
  name prefix, removed in `defer` and by the file's leftover prune); the
  rig's `macscp-test-sshd` is never paused. Docker must be running from the
  main checkout.
- The measurement bound is **10 s**; a close that takes longer than that
  against a silent peer is "does not return" for the purpose of this entry
  (the two calls that DID hang took ≥30 s and returned only on thaw).
- No key material, no secrets; the transfer payload is generated bytes.
- `.swiftLanguageMode(.v6)`; warning budget 1 on a fresh scratch path.
- Commit only what is green. If a measurement shows the close hanging, do
  NOT commit a permanently red test: leave the test uncommitted in the
  report with the numbers, and say so — the follow-up plan commits it as
  its red.

### Task 1: Two measurements — read path and write path

**Files:**
- Modify: `Tests/macSCPAppKitTests/LivenessProbeDropIntegrationTests.swift`
  (new tests beside `teardownAgainstAStillFrozenPeerTerminates`)

**Interfaces:**
- Consumes: `DisposableSSHServer.start(...)`/`connect()`/`freeze()`/`thaw()`/`remove()`
  as they exist in the file (read them; the names above are from a grep,
  the exact factory signature is in the file); `CitadelFileSystem.write(path:contents:mode:)`
  and `readStream(path:offset:)` (exact signatures in
  `Sources/macSCPCore/SSH/CitadelFileSystem.swift` ~lines 700–820).

- [ ] **Step 1: The fixture.** A helper that uploads a generated 8 MB file
  (`Data(repeating: 0x5A, count: 8 << 20)`, or a counting pattern) to the
  disposable server through `fs.write(...)`, so both measurements have a
  real remote file. Prove it: `fs.stat`/list shows the size.
- [ ] **Step 2: Read path.** Test `fileCloseOnTheReadPathAgainstAStillFrozenPeer`:
  connect → start a task that consumes `readStream` for the file in a loop
  → after the FIRST chunk has arrived (signal through the same kind of
  lock-box the file already uses for cross-task state), `server.freeze()`
  → cancel the consuming task → measure with `ContinuousClock` how long
  `await task.value` (or the group's completion) takes to come back;
  record `returned: Bool` and `elapsed` in a box BEFORE `thaw()`. Bound:
  10 s, implemented with a racing sleep the way the existing frozen-peer
  test does — the measurement must not itself hang the suite. Then thaw,
  and only then read anything else. `#expect(returnedBeforeThaw)` with the
  Bool computed first.
- [ ] **Step 3: Write path.** Test `fileCloseOnTheWritePathAgainstAStillFrozenPeer`:
  same shape with `fs.write(path:contents:mode:)` fed by an
  `AsyncStream` of chunks that the test controls — yield one 1 MB chunk,
  wait until it has been written (a box the producer sets after the first
  `yield` was consumed is not enough: wait for the second chunk to be
  requested, which means the first write returned), `freeze()`, yield one
  more chunk (so a write is in flight against the frozen peer), cancel the
  writing task, measure as in Step 2.
- [ ] **Step 4: Three runs each.** `MACSCP_ITEST=1 swift test --filter "fileCloseOnThe"`
  three times; copy all six durations and the six `returned` values into
  the report verbatim.
- [ ] **Step 5: The instrument checked against itself.** Prove the measurement
  can go red: temporarily change the bound to 1 ms (or point the cancel at
  a task that never returns) and see the test fail; restore. One line in
  the report.
- [ ] **Step 6:** If both return: full gated suite once, warnings on a fresh
  scratch path, **commit** — `test(ssh): measure that a file close returns against a frozen peer`.
  If either does not return: commit nothing; report.
