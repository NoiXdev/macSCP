# M15 — S3 Login Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein S3-Login-Set (Access Key ID + Secret) lässt sich anlegen, an eine S3-Session binden und beim Verbinden auflösen — symmetrisch zu SSH-Login-Sets.

**Architecture:** Core bekommt einen eigenen `ResolvedS3Login`-Typ und eine `LoginResolver.resolveS3`-Methode parallel zum bestehenden (unveränderten) SSH-`resolve`. Die App erweitert den Login-Set-Editor um einen kind-Umschalter mit S3-Feldern, die S3-Formularsektion um den Login-Set-Modus (kind-gefilterter Picker), und beide Connect-Füll-Pfade in `ContentView` um einen S3-Zweig. Kein Signer/Transport wird angefasst; die aufgelösten Credentials fließen in den bestehenden `S3ConnectionConfig`-Bau.

**Tech Stack:** Swift (SwiftPM, `.swiftLanguageMode(.v5)`), Swift Testing (`@Test`/`#expect`), SwiftUI + AppKit, macOS 15+, Keychain (`SecretStore`), MinIO-Docker-Rig für gated Tests.

## Global Constraints

- Swift-Targets `.swiftLanguageMode(.v5)`, minimum macOS 15; **keine neue externe Dependency**.
- Tests: Swift Testing, TDD rot→grün; neue Logik kommt mit Tests.
- Unit-Suite `swift test`; gated MinIO `MACSCP_ITEST=1` (+ `MACSCP_KEYCHAIN=1` für Keychain), **immer aus dem Haupt-Checkout, nie aus einem Worktree** (Seed-Mount relativ zur Compose-Datei); Rig `docker compose -f docker/test-server/compose.yml up -d`, MinIO auf **19000/19001**.
- Secret ausschließlich im Keychain unter `set.id` — nie in JSON, Logs oder URLs.
- `LoginResolveError.kindMismatch` ist ein **harter Stopp** — kein Fallback auf falsch-typige Credentials.
- **Kein `if kind == .s3`-Sonderpfad im Signer/Transport**: die Auflösung endet im bestehenden `S3ConnectionConfig`-Bau (`connectS3`), der unverändert bleibt.
- Code/Kommentare/Tests **Englisch**; nutzer-sichtbare Strings über `Localizable.strings` EN/DE/FR/PL, **typografische Anführungszeichen** in nicht-englischen Werten (kein ASCII `"`), FR/PL KI-generiert (Native-Review vor Release).

- [ ] **Step 3: `ResolvedS3Login` + `resolveS3` implementieren**

In `Sources/macSCPCore/Sessions/LoginResolver.swift`, direkt **nach** dem `ResolvedLogin`-Struct (vor `public enum LoginResolver`) einfügen:

```swift
/// S3 credentials resolved from a login set (M15). Parallel to
/// `ResolvedLogin`; the connect path knows the `kind` up front and calls the
/// matching resolver, so S3 gets its own shape rather than an optional field
/// bolted onto the SSH type. `secretAccessKey` is the set's keychain entry
/// (under `set.id`), nil when none is stored.
public struct ResolvedS3Login: Equatable, Sendable {
    public var accessKeyID: String
    public var secretAccessKey: String?

    public init(accessKeyID: String, secretAccessKey: String?) {
        self.accessKeyID = accessKeyID
        self.secretAccessKey = secretAccessKey
    }
}
```

Innerhalb `public enum LoginResolver`, direkt **nach** der bestehenden `resolve(session:sets:secrets:)`-Methode einfügen:

```swift
    /// Resolves a session's S3 login (M15): `nil` for a manual S3 session
    /// (loginSetID == nil — the caller uses the session's own access key),
    /// the set's access key + keychain secret otherwise. Mirrors `resolve`
    /// above: a dangling reference throws `.missingSet`, and binding a set of
    /// a different protocol (an S3 session referencing an SSH set) throws
    /// `.kindMismatch` — a hard stop, never a fallback to wrong-kind creds.
    public static func resolveS3(
        session: StoredSession, sets: [LoginSet], secrets: any SecretStore
    ) throws -> ResolvedS3Login? {
        guard let setID = session.loginSetID else { return nil }
        guard let set = sets.first(where: { $0.id == setID }) else {
            throw LoginResolveError.missingSet
        }
        guard set.kind == session.kind else {
            throw LoginResolveError.kindMismatch
        }
        let secret = (try? secrets.password(for: set.id)) ?? nil
        return ResolvedS3Login(accessKeyID: set.accessKeyID ?? "", secretAccessKey: secret)
    }
```
