# M10d — ssh-agent authentication implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent auth as a third auth kind everywhere (form target + jump, login sets, stored sessions): macSCP speaks the ssh-agent protocol over `SSH_AUTH_SOCK` itself; the private key never leaves the agent. NO forwarding (its own future fork milestone).

**Architecture:** A pure `SSHAgentCodec` + `SSHAgentClient` with an injectable transport (production: NIO `ClientBootstrap` onto the UDS path); `AgentBackedPrivateKey: NIOSSHPrivateKeyProtocol` via the official custom-signer hook (`NIOSSHPrivateKey.init(custom:)`, modeled on Citadel's `Insecure.RSA.PrivateKey`); `AuthMethod.agent` offers the identities in order (OpenSSH behavior); `AuthKind.agent` flows through StoredSession/JumpSpec/login sets/resolver/merge/export. App: third auth segment on target, jump, and set editor.

**Tech Stack:** Swift 6 / `.swiftLanguageMode(.v5)`, Swift Testing, NIOPosix (present transitively), SwiftUI.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-m10d-ssh-agent-design.md` — binding (including feasibility line citations). Branch: **develop**.
- The private key NEVER leaves the agent; macSCP stores NO secrets for agent logins (keychain untouched; slot hygiene on switching to `.agent` just like on a set switch).
- TOFU INVARIANTS UNTOUCHED (both hops); the M10c retry loop stays semantically unchanged — `.agent` only changes how the auth method is built. The auth method continues to be built FRESH PER ATTEMPT (M10c lesson: `SSHAuthenticationMethod` consumes its list).
- Identities are listed ONCE per connect (before the retry loop); each identity is offered exactly ONCE per attempt (bounded).
- Honest errors: `SSH_AUTH_SOCK` missing/dead and "no identities" are THEIR OWN localized messages, not a generic auth-failed; all identities rejected ⇒ `authenticationFailed` (jump hop: `jumpAuthenticationFailed`, existing stage classification).
- Downgrade boundary deliberately accepted (spec §4): no sessions.json hardening against old app versions.
- All new UI texts EN/DE (both app catalogs), Core error texts in both Core catalogs; code + comments English ONLY; NO new dependencies (NIOPosix is present transitively — adding it in Package.swift as a direct dependency of the Core target is ALLOWED, no new package).
- Conventional Commits (English), footer: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- `swift build` + full `swift test` green after every task (starting point: 532 tests / 40 suites); gated suites in T2 and T5; tests run SYNCHRONOUSLY in the foreground; TDD red→green for Core.
- Docker rig only `start`/`stop` from the main checkout; the gated agent test starts its OWN `ssh-agent` process and ends it in teardown (never touch the user's own agent).
- NO release, no merge to main.

### Task 1: SSHAgentCodec + SSHAgentClient (Core, RISK)

**Files:**
- Create: `Sources/macSCPCore/SSH/SSHAgentCodec.swift`, `Sources/macSCPCore/SSH/SSHAgentClient.swift`
- Modify: `Package.swift` ONLY if `NIOPosix`/`NIOCore` are missing as a direct dependency of the Core target (present transitively; no new package)
- Test: `Tests/macSCPCoreTests/SSHAgentCodecTests.swift`, `Tests/macSCPCoreTests/SSHAgentClientTests.swift` (new)

**Interfaces:**
- Produces (T2 relies on this exactly):
  - `AgentIdentity: Equatable, Sendable` (`publicKeyBlob: Data`, `comment: String`, `keyType: String` [parsed from the blob, e.g. "ssh-ed25519"], `fingerprintSHA256: String`)
  - `AgentError: Error, Equatable, Sendable` (`socketUnavailable`, `noIdentities` [T2 throws it — T1 only defines it], `refused`, `protocolError(reason: String)`)
  - `SSHAgentCodec` (enum, pure): `requestIdentitiesFrame() -> Data`, `signRequestFrame(publicKeyBlob: Data, data: Data, flags: UInt32) -> Data`, `parseIdentitiesAnswer(_ frame: Data) throws -> [AgentIdentity]`, `parseSignResponse(_ frame: Data) throws -> Data` [returns the raw `string` payload: algo name + sig blob], `readFrame` helper (uint32 length + body)
  - `protocol SSHAgentTransport: Sendable` (`func roundTrip(_ request: Data) async throws -> Data` [one frame out, one frame in], `func close() async`)
  - `SSHAgentClient` (`init(transport:)` + `static func connect(socketPath: String) async throws -> SSHAgentClient` [NIO ClientBootstrap onto the UDS; connection error ⇒ `AgentError.socketUnavailable`]): `listIdentities() async throws -> [AgentIdentity]`, `sign(publicKeyBlob: Data, data: Data, flags: UInt32) async throws -> Data`, `close() async`
  - Flag constants: `SSHAgentCodec.rsaSHA2_256: UInt32 = 2`, `rsaSHA2_512: UInt32 = 4`

**Protocol (binding, ssh-agent draft-miller):** Frame = `uint32 length` + body; body = `byte type` + payload. Requests: REQUEST_IDENTITIES=11, SIGN_REQUEST=13 (`string key blob`, `string data`, `uint32 flags`). Responses: IDENTITIES_ANSWER=12 (`uint32 n`, then n× `string blob` + `string comment`), SIGN_RESPONSE=14 (`string signature`), FAILURE=5 ⇒ `.refused`. Anything else/truncated ⇒ `.protocolError`. Fingerprint: SHA256 over the blob, Base64 without padding, prefix `SHA256:` — the M3c format (grep `fingerprintSHA256` in `KnownHostsStore.swift`/`HostKeyValidation` and use the same derivation pattern; reuse the helper if exposed, otherwise mirror it locally and note that in the report).

- Produces (T3/T4 rely on this exactly):

  - `CitadelFileSystem.connect` understands `.agent` on target AND jump; signature unchanged
  - `AgentAuthDelegate: NIOSSHClientUserAuthenticationDelegate` (internal; `init(username:identities:client:)` — offers the identities in order as a `.privateKey` offer with `NIOSSHPrivateKey(custom: AgentBackedPrivateKey(...))`, then fails)
  - Test hook: `CitadelFileSystem` gets an injectable `agentClientFactory: @Sendable (String) async throws -> SSHAgentClient` (default: `SSHAgentClient.connect(socketPath:)`) OR the smaller solution the implementer documents — the mock tests must be able to drive the auth flow WITHOUT a real socket

**Behavioral requirements (spec §2, binding):**
1. `.agent` on the target: `connect()` reads `SSH_AUTH_SOCK` from the process environment ONCE, connects the agent client, `listIdentities()`; `[]` ⇒ `AgentError.noIdentities`; socket error ⇒ `.socketUnavailable`. Both happen BEFORE the TOFU retry loop (the identity list is reused across attempts; the client stays open for signatures and is closed after connect ends — success as well as failure).
2. Per connection attempt the auth method is built FRESH (M10c lesson); the delegate offers each identity exactly once. `AgentBackedPrivateKey.signature(for:)` calls `client.sign(publicKeyBlob:data:flags:)` — flags: 0 for non-RSA; for `ssh-rsa` blobs `rsaSHA2_512`. IMPORTANT, verify against the vendored sources (implementer's duty, cite it in the report): how the algorithm name in the userauth request is derived from `publicKey.keyPrefix` vs. the signature — for RSA the request must carry `rsa-sha2-512`, while the blob type stays `ssh-rsa` (OpenSSH semantics; Citadel's RSA code shows the spot). The gated RSA test is the proof.
3. `AgentSignature`/`AgentBackedPublicKey` re-emit the agent bytes VERBATIM (`write(to:)` writes algo name + sig blob exactly as received; PublicKey writes the identity blob unchanged; `keyPrefix` from the blob type, or for RSA from the request algorithm per point 2).
4. `.agent` on the JUMP: identical build in stage-1 auth; `socketUnavailable`/`noIdentities` on the jump run through the existing JumpStageError classification (⇒ message carries jump context); complete rejection ⇒ `jumpAuthenticationFailed`. Target unchanged: `authenticationFailed`.
5. Error mapping in `mapConnectError`/`mapStageAware`: `AgentError` is passed through (typed, NOT stringified into connectionFailed — M10c lesson: preserve type); ConnectionViewModel maps to localized texts in T4 (T2 only delivers the typed errors).
