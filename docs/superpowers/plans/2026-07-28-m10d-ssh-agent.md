# M10d — ssh-agent-Authentifizierung Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent-Auth als dritte Auth-Art überall (Formular Ziel + Jump, Login-Sets, gespeicherte Sessions): macSCP spricht das ssh-agent-Protokoll über `SSH_AUTH_SOCK` selbst; der private Schlüssel verlässt den Agent nie. KEIN Forwarding (eigener Fork-Meilenstein).

**Architecture:** Purer `SSHAgentCodec` + `SSHAgentClient` mit injizierbarem Transport (produktiv NIO-`ClientBootstrap` auf den UDS-Pfad); `AgentBackedPrivateKey: NIOSSHPrivateKeyProtocol` über den offiziellen Custom-Signer-Haken (`NIOSSHPrivateKey.init(custom:)`, Vorbild Citadels `Insecure.RSA.PrivateKey`); `AuthMethod.agent` bietet die Identitäten der Reihe nach an (OpenSSH-Verhalten); `AuthKind.agent` fließt durch StoredSession/JumpSpec/Login-Sets/Resolver/Merge/Export. App: drittes Auth-Segment an Ziel, Jump und Set-Editor.

**Tech Stack:** Swift 6 / `.swiftLanguageMode(.v5)`, Swift Testing, NIOPosix (transitiv vorhanden), SwiftUI.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-28-m10d-ssh-agent-design.md` — bindend (inkl. Machbarkeits-Zeilenbelege). Branch: **develop**.
- Der private Schlüssel verlässt NIE den Agent; macSCP speichert für Agent-Logins KEINE Secrets (Keychain unberührt; Slot-Hygiene beim Wechsel auf `.agent` wie beim Set-Wechsel).
- TOFU-INVARIANTEN UNANGETASTET (beide Hops); die M10c-Retry-Schleife bleibt semantisch unverändert — `.agent` ändert nur den Auth-Methoden-Bau. Auth-Methode wird weiterhin FRISCH PRO VERSUCH gebaut (M10c-Lektion: `SSHAuthenticationMethod` konsumiert seine Liste).
- Identitäten werden EINMAL pro Connect gelistet (vor der Retry-Schleife); jede Identität wird pro Versuch genau EINMAL angeboten (bounded).
- Ehrliche Fehler: `SSH_AUTH_SOCK` fehlt/tot und „keine Identitäten" sind EIGENE lokalisierte Meldungen, kein generisches Auth-failed; alle Identitäten abgelehnt ⇒ `authenticationFailed` (Jump-Hop: `jumpAuthenticationFailed`, bestehende Stage-Klassifikation).
- Downgrade-Grenze bewusst akzeptiert (Spec §4): keine sessions.json-Absicherung gegen alte App-Versionen.
- Alle neuen UI-Texte EN/DE (beide App-Kataloge), Core-Fehlertexte in beiden Core-Katalogen; Code + Kommentare NUR Englisch; KEINE neuen Dependencies (NIOPosix ist transitiv da — im Package.swift als direkte Dependency des Core-Targets ergänzen ist ERLAUBT, kein neues Paket).
- Conventional Commits (Englisch), Footer: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- `swift build` + volle `swift test` nach jedem Task grün (Ausgangslage 532 Tests / 40 Suiten); gated Suiten in T2 und T5; Tests SYNCHRON im Vordergrund; TDD rot→grün für Core.
- Docker-Rig nur `start`/`stop` aus dem Haupt-Checkout; der gated Agent-Test startet seinen EIGENEN `ssh-agent`-Prozess und beendet ihn im Teardown (nie den Agent des Users anfassen).

**Files:**

- Test: `Tests/macSCPCoreTests/SSHAgentCodecTests.swift`, `Tests/macSCPCoreTests/SSHAgentClientTests.swift` (neu)

**Interfaces:**
- Produces (T2 verlässt sich exakt hierauf):
  - `AgentIdentity: Equatable, Sendable` (`publicKeyBlob: Data`, `comment: String`, `keyType: String` [aus dem Blob geparst, z. B. "ssh-ed25519"], `fingerprintSHA256: String`)
  - `AgentError: Error, Equatable, Sendable` (`socketUnavailable`, `noIdentities` [T2 wirft ihn — T1 definiert nur], `refused`, `protocolError(reason: String)`)
  - `SSHAgentCodec` (enum, pur): `requestIdentitiesFrame() -> Data`, `signRequestFrame(publicKeyBlob: Data, data: Data, flags: UInt32) -> Data`, `parseIdentitiesAnswer(_ frame: Data) throws -> [AgentIdentity]`, `parseSignResponse(_ frame: Data) throws -> Data` [liefert die rohe `string`-Payload: Algo-Name + Sig-Blob], `readFrame`-Helfer (uint32-Länge + Body)
  - `protocol SSHAgentTransport: Sendable` (`func roundTrip(_ request: Data) async throws -> Data` [ein Frame raus, ein Frame rein], `func close() async`)
  - `SSHAgentClient` (`init(transport:)` + `static func connect(socketPath: String) async throws -> SSHAgentClient` [NIO ClientBootstrap auf UDS; Verbindungsfehler ⇒ `AgentError.socketUnavailable`]): `listIdentities() async throws -> [AgentIdentity]`, `sign(publicKeyBlob: Data, data: Data, flags: UInt32) async throws -> Data`, `close() async`
  - Flag-Konstanten: `SSHAgentCodec.rsaSHA2_256: UInt32 = 2`, `rsaSHA2_512: UInt32 = 4`

**Protokoll (bindend, ssh-agent draft-miller):** Frame = `uint32 length` + Body; Body = `byte type` + Payload. Requests: REQUEST_IDENTITIES=11, SIGN_REQUEST=13 (`string key blob`, `string data`, `uint32 flags`). Antworten: IDENTITIES_ANSWER=12 (`uint32 n`, dann n× `string blob` + `string comment`), SIGN_RESPONSE=14 (`string signature`), FAILURE=5 ⇒ `.refused`. Alles andere/Truncated ⇒ `.protocolError`. Fingerprint: SHA256 über den Blob, Base64 ohne Padding, Präfix `SHA256:` — das M3c-Format (grep `fingerprintSHA256` in `KnownHostsStore.swift`/`HostKeyValidation` und dasselbe Ableitungs-Muster verwenden; Helfer wiederverwenden falls exponiert, sonst lokal spiegeln und das im Report notieren).

**Verhaltens-Anforderungen (Spec §2, bindend):**
1. `.agent` am Ziel: `connect()` liest `SSH_AUTH_SOCK` aus der Prozess-Umgebung EINMAL, verbindet den Agent-Client, `listIdentities()`; `[]` ⇒ `AgentError.noIdentities`; Socket-Fehler ⇒ `.socketUnavailable`. Beides passiert VOR der TOFU-Retry-Schleife (die Identitätenliste wird über die Versuche wiederverwendet; der Client bleibt für die Signaturen offen und wird nach Connect-Ende — Erfolg wie Fehler — geschlossen).
2. Pro Verbindungsversuch wird die Auth-Methode FRISCH gebaut (M10c-Lektion); der Delegate bietet jede Identität genau einmal an. `AgentBackedPrivateKey.signature(for:)` ruft `client.sign(publicKeyBlob:data:flags:)` — flags: 0 für nicht-RSA; für `ssh-rsa`-Blobs `rsaSHA2_512`. WICHTIG, gegen die vendorten Quellen verifizieren (Implementer-Pflicht, im Report belegen): wie der Algorithmus-Name im userauth-Request aus `publicKey.keyPrefix` bzw. der Signatur abgeleitet wird — für RSA muss der Request `rsa-sha2-512` tragen, während der Blob-Typ `ssh-rsa` bleibt (OpenSSH-Semantik; Citadels RSA-Code zeigt die Stelle). Der gated RSA-Test ist der Beweis.
3. `AgentSignature`/`AgentBackedPublicKey` re-emittieren die Agent-Bytes VERBATIM (`write(to:)` schreibt Algo-Name + Sig-Blob exakt wie erhalten; PublicKey schreibt den Identity-Blob unverändert; `keyPrefix` aus dem Blob-Typ bzw. für RSA der Request-Algorithmus gem. Punkt 2).
4. `.agent` am JUMP: identischer Bau in der Stage-1-Auth; `socketUnavailable`/`noIdentities` beim Jump laufen durch die bestehende JumpStageError-Klassifikation (⇒ Meldung trägt Jump-Kontext); komplette Ablehnung ⇒ `jumpAuthenticationFailed`. Ziel unverändert `authenticationFailed`.
5. Fehler-Mapping in `mapConnectError`/`mapStageAware`: `AgentError` wird durchgereicht (typisiert, NICHT zu connectionFailed stringifiziert — M10c-Lektion Typ-Erhalt); ConnectionViewModel mappt in T4 auf lokalisierte Texte (T2 liefert nur die typisierten Fehler).
