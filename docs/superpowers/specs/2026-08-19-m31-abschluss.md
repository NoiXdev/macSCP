# M31 — Wrap-up (2026-08-19)

Spec: `2026-08-19-m31-adhoc-audit-design.md`
Plan: `../plans/2026-08-19-m31-adhoc-audit.md`

## What was implemented

A connection that isn't saved now still writes its audit entry. Attaching
the `AuditRecorder` no longer sits inside `if form.shouldSaveSession`; the
session ID comes from `AdHocAudit.logSessionID(storedID:)` — a saved
session → its ID, otherwise the fixed ad-hoc ID. An entry in the
Sessions menu opens this log in the existing audit sheet.

This also brings back the **M21 plaintext note**, which until now was
missing for precisely the connections that weren't saved.

Suite: **2168 tests in 194 suites green** (previously 2165).

## Verification

The central guarantee — "attaching no longer depends on saving" — was
checked, with a positive control:

| Check | Result |
|---|---|
| `attachAuditRecorder` inside the `shouldSaveSession` branch | 0 |
| same string across the whole file (positive control) | 4 |

The second number is the point: if it were also 0, the first would be
measuring nothing and its "success" would be worthless. M26 made exactly
this mistake once — a plan grep didn't run at all under zsh and would
have been logged as proof anyway.

## Errors in the plan

One, found and fixed in self-review before implementation: the plan
**set** `tabCommands.showAdHocAuditLog` without ever declaring the
property. An implementer would have gotten stuck on a compiler error
whose cause wasn't in the plan.

One more surfaced during execution, which caused no harm: the plan
placed the wiring in `ContentView+Detail.swift`. That's where the
sidebar callbacks live; the menu closures are assigned in
`ContentView+Lifecycle.swift`, next to `showSSHKeys`. Checked, instead of
missed.

## What remains open

- **No global audit view.** Deliberately left out (M27); this design
  doesn't need it, it uses the existing session view.
- **Visual check still outstanding:** that the menu entry appears and
  the sheet shows the ad-hoc entries has been seen by no test — no test
  in this repo launches the GUI. Belongs on the list of visual checks
  for the maintainer.
- Whether several ad-hoc connections in one shared log stay readable
  **in practice** will only show with use. The rows carry host and user
  in the detail text; if that gets too cramped, a grouping in the sheet
  would be the next step — not a second ID.
